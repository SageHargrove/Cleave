# Engineering practice

Cleave holds real enterprise access data. Claims about privacy and correctness
are only worth anything if the process behind them is checkable, so this document
describes the process rather than asserting the outcome.

## One command is the whole gate

```
nox -s gate
```

That is exactly what CI runs, so "works on my machine" and "passes CI" cannot
diverge. It chains:

| Session | What it enforces |
|---|---|
| `lint` | `ruff check` |
| `format` | `ruff format --check` |
| `typecheck` | `mypy`, strict on `cleave.engine` |
| `boundaries` | the import-linter architecture contracts |
| `test` | `pytest` with the engine coverage floor |
| `audit` | `pip-audit` against the hashed lockfile |

Separate sessions cover the things that should not gate every commit:
`perf` (the slow full-scale performance tests), `frontend` (npm ci, typegen
freshness, eslint, vitest, SPA build), `e2e` (Playwright against a real server),
`sbom` (CycloneDX generation), and `openapi` (contract regeneration).

The gate is deliberately **Node-free**. The Python toolchain never needs npm
installed, which keeps the backend contributor experience small.

CI runs the gate on an OS matrix, because a product that ships as a local binary
on someone's laptop cannot be Linux-only in practice.

## Testing

**1,045 tests, all green.** Engine coverage sits at **98.4%** against an 85%
floor. Golden-file tests pin analysis output wherever output is stable, so a
change to scoring shows up as a diff rather than a vibe.

Three properties get tested that are easy to skip:

**Determinism.** A test asserts that findings, scores, and fingerprints are
byte-identical with the AI layer on and off, which is how "AI is advisory only"
stops being a promise and starts being a checkable fact.

**No egress.** The test sandbox blocks outbound network access while permitting
loopback. An accidental call to the outside world fails the build. This is the
enforcement mechanism behind the local-first claim, and it is why the AI layer's
tests use fake transports rather than a network allowlist.

**Refactors that must not change behavior.** When outlier scoring was rewritten
for memory, the old algorithm was frozen into `tests/engine_outliers_reference.py`
and the new one was proven bit-identical against it across four generated
companies, a threshold sweep, risk overrides, and overlapping groupings. A
`tracemalloc` shape guard (150 bytes per pair, against the old shape's 574) was
written so that it **provably fails against the old algorithm**, which is the
only way to know a performance guard actually guards anything.

**End to end.** The Playwright suite runs the built SPA against the real FastAPI
server with a real worker-job backend, seeded by the synthetic generator. No
mocked responses anywhere. It caught two real defects before any user could:
cache invalidation never firing for quick-submit jobs, and offset-less run
timestamps rendering as local time.

## Supply chain

`uv` manages the environment and `uv.lock` pins exact versions **with hashes**.
`requirements-dev.txt` is the exported hashed set that the gate installs from, so
local, pre-commit, and CI resolve identically. A CycloneDX SBOM is generated by
`nox -s sbom`, and `pip-audit` runs inside the gate.

This posture is load-bearing rather than decorative, and it decided at least one
architectural question outright. See
[decisions/0001](decisions/0001-reportlab-over-weasyprint.md), where a PDF
library was rejected because its native rendering stack sat outside the hashed
lock, invisible to `pip-audit` and absent from the SBOM.

The locker is intentionally swappable. If `uv` becomes painful, `pip-tools`
produces an equivalent hashed requirements file and nothing else changes.

## Security review

Every change touching `ingest`, `core`, `web`, or `ai` gets an adversarial review
of the **diff, before it is committed**. `ingest` is non-negotiable because it
parses untrusted customer files and is the highest-risk surface in the product.

This has repeatedly paid for itself:

- CSV formula injection in the quarantine export, fixed at source with a single
  un-bypassable writer covering XLSX as well as CSV. The guard immediately caught
  a direct worksheet write added later for a truncation notice.
- A ReportLab `<img src>` tag inside an unescaped cover string, which **embeds an
  arbitrary local file into the generated PDF**. Measured, not theorized.
- An HTML comment break-out in the IIQ role-export provenance header.
- A change that would have reported roughly 85% of prior findings as
  *remediated* on the first upgrade run and written them all back as resolved
  rows. Caught before merge. This became
  [decisions/0006](decisions/0006-comparability-as-a-precondition.md).

## The end-of-project review sweep

After the last capability shipped, the whole codebase went through eight parallel
deep reviews, one per module plus build and CI, followed by verify, fix, and
re-review.

It found **three critical defects, all in `ingest`, all reproduced rather than
argued**:

1. The XLSX cell limit was computed from the workbook's own `<dimension>` element.
   Omitting that element zeroed the limit, and *understating* it silently imported
   a subset. A 2,000-row file imported **1 row**, which downstream reads as mass
   deprovisioning.
2. Merged-cell forward fill filled every blank cell rather than merged ranges,
   because read-only mode exposes no merged list. This fabricates identifiers,
   attributing one person's access to another.
3. An unrecognized `status` value quarantined the entire identity, and both
   shipped sample files triggered it (`userAccountControl` 66048 for AD,
   `PROVISIONED` for Okta).

Plus two high-severity data-integrity defects in `core` (a byte-identical
repeated row aborting a whole import on a unique violation; undo ordered by
staging time replaying the wrong journal over committed data), and the finding
that the AI redaction boundary trusted key *names* rather than values.

Two of the fixes in that sweep introduced regressions, which self-review then
caught and pinned with tests. That is recorded here rather than quietly dropped,
because a review process that never reports its own misses is not reporting
honestly.

One defect was deliberately **not** fixed: non-Latin-1 names rendered as
dingbats in the PDF, because Helvetica is WinAnsi-encoded and the fix is an
embedded Unicode font, which is a dependency decision rather than a bug fix. It
was scheduled and shipped separately.

## How work is organized

Development runs on [OpenSpec](https://github.com/Fission-AI/OpenSpec). Each
capability is a change with a written proposal, design document, delta specs, and
task list authored **before** implementation, then archived into a permanent
spec on completion. Requirement IDs are the contract and commits cite them.

The discipline that makes this worth the overhead is that design documents record
open questions as open, and the answers arrive as **measurements**. Nearly every
entry in [decisions/](decisions/) exists because a design document said "we do
not know yet, here is how we will find out," and then someone found out.

Several of those measurements refuted the design they were testing. Those are the
entries worth reading.
